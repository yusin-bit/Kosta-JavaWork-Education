05대여 승인 트랜잭션

승인은 세 개의 변경이 한 묶음입니다. 하나라도 실패하면 전부 취소해서 데이터가 어긋나지 않게 합니다.

flowchart LR
  T0(["autoCommit = false"]) --> T1["① 같은 게시글의
다른 신청 거절"]
  T1 --> T2["② 이 신청 승인
(본인 물품인지 확인)"]
  T2 --> T3["③ 물품 상태를
대여 불가로 변경"]
  T3 --> Q{"모두 성공?"}
  Q -- "예" --> OK(["commit"])
  Q -- "아니오" --> NG(["rollback"])

07구현 포인트

계층 분리

View → Controller → Service → Repository. 인터페이스와 구현 클래스를 나눠 역할을 분리했습니다.

트랜잭션 처리

대여 승인과 최종 완료 시 여러 UPDATE를 한 트랜잭션으로 묶고, 실패하면 rollback 합니다.

상태를 조건으로 한 UPDATE

WHERE status = 현재 상태 조건으로 갱신해서, 순서에 맞지 않는 상태 변경이 일어나지 않습니다.

단계별 권한 확인

단계마다 처리 주체(빌리는 사람/빌려주는 사람)를 정해 두고, 로그인한 사용자와 맞는지 DB에서 확인합니다.

중복 신청 방지

대여 신청 INSERT에 NOT EXISTS를 써서 같은 사람의 진행 중 중복 신청과 본인 물품 신청을 막습니다.

PreparedStatement 사용

모든 SQL에 파라미터 바인딩을 사용해 SQL 인젝션을 방지합니다.

DB 뷰 활용

반복되는 조인을 뷰 3개로 모아 조회 코드를 단순하게 만들었습니다.

두 가지 화면, 하나의 서비스

콘솔 앱과 로컬 웹(내장 HttpServer)이 같은 Service 계층을 호출해 업무 규칙을 한 곳에서 관리합니다.

소스와 resources/MiniProject_table.sql을 기준으로 작성했습니다.
